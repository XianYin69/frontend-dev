# 需求理解

操作节点。明确「改什么、改成什么样、怎么算完成」。

## 输入 / 动作

1. 确认目标页面或组件路径；不确定时列候选让用户选。
2. 判定改动类型：新增页面 / 修改内容 / 样式调整 / 交互逻辑 / 框架引入。
3. 读项目上下文：目录结构、双语映射（如 zh-CN ↔ en-US）、同类模板页范式。
4. 产出 change-plan（目标·范围·验收标准），交用户确认后再动代码。

## 约束

- 不可逆操作（覆盖写、删除、push）必须先在 change-plan 中声明并获确认。
- 双语站改动默认要求双语同步，除非用户显式豁免。

## 决策分支

- 素材/范式不明 → 检索 `references/` 与既有页面；仍不足 → 联网查询补经验。
- 通过 → [现状核对](../现状核对/现状核对.md)
